Cakify

用 GPUI + Rust 做一个启动快、内存低，但聊天功能不缩水的原生客户端。整体能力向 Cherry Studio 与 RikkaHub 看齐，工具交互参考 Zed；不做知识库/RAG、远程操控、云同步和重量常驻运行时。

产品范围

必须做完整

  • 多 Provider、多模型、自定义兼容 endpoint。
  • 会话 CRUD、搜索、分支、归档与导入导出。
  • 流式聊天、停止、重试、编辑重发、重新生成。
  • Markdown、代码块、图片/文件附件、提示词。
  • function/tool calling、审批、取消、错误恢复。
  • MCP stdio/Streamable HTTP、启停和会话绑定。
  • 主题、快捷键、草稿、数据与隐私管理。

明确不做

  • 知识库、RAG、embedding、向量数据库。
  • 远程操控、无人值守代理、远程桌面。
  • 云账号、跨设备同步、团队后台。
  • 内置下载与管理本地大模型。
  • 自动安装第三方 Node/Python 插件。
  • 默认任意 shell、多 Agent 自动编排。

范围判断：这是“轻量但完整的 AI Chat”，不是功能演示壳。RAG、远控和云服务不是普通待办，而是防止产品重新臃肿的硬边界。

系统架构

默认只有一个 cakify.exe。GPUI 在主线程处理输入和渲染，Rust Core 在独立服务线程处理网络、Provider、Agent 与 MCP；SQLite 由单独 actor 独占连接。只有用户启用的 MCP 或工具可以启动子进程。

Zed 的作用

Zed 已证明 GPUI 可以承载成熟 Agent 对话，包括输入、消息队列、上下文、工具时间线与权限。但其 agent/agent_ui 是 GPL-3.0-or-later；Cakify 只参考公开行为和 GPUI API，用独立领域模型与实现。Apache-2.0 的 gpui-component 在 M0 revision 兼容门未通过，当前按 ADR 0002 直接使用 GPUI primitives，未来满足固定 revision、IME、Markdown、体积和依赖门后再评估。

数据与安全

本地数据

  • SQLite 保存会话、消息 parts、run、tool call、设置与引用。
  • 附件按 SHA-256 放在 %LOCALAPPDATA%\Cakify。
  • WAL + foreign keys + migration；live backup 走 SQLite Backup API。
  • 崩溃后 running 变为 interrupted，不自动重跑工具。
  • 本地搜索只用 FTS5，不加入 embedding/RAG。

秘密与权限

  • API Key/OAuth token 进入 Credential Manager。
  • 结构化 secret 必要时用 DPAPI current-user；禁止 machine scope。
  • SQLite 只保存 opaque credential reference。
  • 工具默认 confirm，MCP 与内建工具共用权限模型。
  • 日志、导出、artifact 默认排除 secret 和原始 payload。

边界：Credential Manager/DPAPI 解决静态密钥保护，不抵抗已经控制同一 Windows 用户会话的恶意软件；权限弹窗也不等于进程 sandbox。

构建与发布

本机只编辑源码，编译、测试、基准、打包和发布都在 GitHub Actions。产品 workflow 分为 validate、Windows smoke、benchmark、package 与 release，默认使用假 Provider 和合成 secret。

2026 年 8 月限制：私库 Actions 分钟已耗尽，workflow 只能手动触发。完成可交付源码或产品功能后仍须自动 commit/push，并在验证通过后自动递增预览版本、运行统一 Release workflow、发布安装器、便携 ZIP、独立 EXE 与校验文件。用户已持续授权本月受控临时公开和预览发版闭环：无新增实质风险时自动临时公开、运行当前任务所需 workflow、核对 artifact 与 Release、确认无活动任务，再立即恢复私有。文档-only、测试-only、CI-only 或用户明确不发版的改动可只推送；长期公开、正式稳定版语义、无关 workflow 或新增安全/许可证/数据风险仍需另行确认；进入 9 月先核实额度和规则。
